# 插件机制与使用审计（2026-11-01）

## 1. 审计目标

本次审计关注工程边界，而不是证明摘要语义相似度：

- 压缩后端出错或 payload 不完整时，本插件不能拖垮压缩或宿主 step；
- DSH 插件加载、配置、注册和卸载路径可预测；
- 索引存储不可读、损坏或不可写时，仍能尽量降级；
- 上下文压缩后，P0 字面量和 source seq 指针不会静默丢失；
- 工具只读，不重放工具调用，不越界读取其它 session。

## 2. 测试环境

- DSH API 包：dsh-tools、dsh-llm、dsh-session 均为 0.2.1-rc.2；
- cordis 4.0.5、schemastery 3.18.5、Node 24.21.0；
- 同时保留 session format v3/v4 的 producer source 分支；
- 测试文件：core.test.mjs、store.test.mjs、plugin.test.mjs。

## 3. 已发现并修复的问题

| 问题 | 风险 | 修复 |
|---|---|---|
| 配置只由手写 normalizeConfig 兜底 | 插件管理器无法提前拒绝非法枚举/负数 | 导出 Schemastery Config，并由运行时再次 clamp |
| session/event 是 fire-and-forget | 漏一次通知后可能永远没有索引 | 首次 backfill + scanNewSummaries 增量补偿扫描 |
| 活 session 状态 Map 无上限 | 长进程/多 session 下内存持续增长 | maxTrackedSessions + 最近使用淘汰；淘汰后从 JSONL 重载 |
| shadowedSeqs 缺失 | 伪造 range 会制造错误指针 | 明确 quarantine 为 shadowed-seqs-missing |
| 单个源事件读取异常 | 整个索引流程可能中断 | 缺失 seq 进入 quarantine 诊断，不抛出到宿主 |
| 长工具输出/JSON 参数截断 | 静默漏 P0 | 显式 sampled/truncated 标志并 quarantine |
| JSON tool arguments 中的 Windows 路径被双重转义 | 锚点与摘要中的语义路径不一致 | 解析 tool arguments 的语义文本；读取时展示 semantic + raw |
| 索引目录不可读/不可写 | 工具和 step 可能整体失败 | 读失败转内存索引；写失败记 warning；pre-step 保持原 decision |
| 旧 session 被内存淘汰 | 工具可能误报没有索引 | 工具调用前按需重载 append-only store |
| Config 与默认值可能漂移 | 插件管理器和运行时行为不一致 | 测试断言 Config key 集合与 naming 声明一致 |

## 4. 故障注入结果

- 缺失 shadowedSeqs：条目被隔离，pre-step 注入 QUARANTINED 卡，宿主 flow 正常；
- indexRoot 指向普通文件：load/append 失败被 warning 吞掉，当前进程内仍可 search；
- 4 个 session 并发使用 maxTrackedSessions=2：最早 session 被淘汰后仍能从 store 重载；
- JSONL 中间出现坏行：坏行计数，其余有效条目继续可读；
- 索引文件超过读取窗口：仅加载尾部完整 JSONL 窗口并告警；
- 重复 pre-step：同一 compaction 的索引卡只注入一次；
- inject=false：不产生 pre-step 注入消息，三个工具仍可查询；
- 工具注册：仅注册 sumidx_search、sumidx_read、sumidx_probe，没有 compaction service 注册；
- 隔离 DSH_HOME 下执行 dsh plugin add 本地 tarball：依赖写入成功，dsh.profile.bundles 自动加入 dsh-summary-index，--dump-config 显示 summary-index 行；
- 生产依赖 npm audit --omit=dev：0 vulnerabilities。

## 5. 无法在非接管架构中消除的限制

1. compaction/summary 已提交后不能回滚；守卫只能隔离索引，不能撤销压缩。
2. 原文读取依赖 live session store；session 不在内存时只能保留指针。
3. 确定性探针检查字面量和指针可达性，不做语义蕴含证明。
4. JSONL 写入是进程内串行；同一 session 被多个进程同时写不在保证范围内。
5. 原文事件读取可能暴露会话中已有的敏感内容，默认由工具显式按 seq 读取。

## 6. 审计结论

在 DSH 0.2.1-rc.2 API 包、Node 24 环境下，29 个测试通过；插件加载、配置校验、工具注册、压缩事件异常、索引读写故障和 pre-step 注入均有覆盖。剩余风险已在上节列出，其中第一条属于非接管式 postprocessor 的架构约束，不能通过本插件内部代码消除。
